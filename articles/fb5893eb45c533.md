## 起きたこと

Claude Code に「PRを作って」と頼むと、リポジトリの `.github/PULL_REQUEST_TEMPLATE.md` を無視した本文が出てくることがありました。

うちのリポジトリでは、AGENTS.md（Claude Code 用の指示ファイル）にこう書いていました。

```md
- PRの本文は `.github/PULL_REQUEST_TEMPLATE.md` の構成に従う
- 内容のないセクションは削除する

一見これで十分そうに見えます。実際、GitHubのWeb UI経由で人間がPRを作るときは何も意識しなくてもテンプレートが自動で読み込まれます。ところがClaude Codeが gh pr create を使ってPRを作ると、空の見出しが残ったままだったり、そもそもテンプレートと違う構成の本文になったりすることがありました。

なぜ gh pr create では効かないのか

GitHubのWeb UIは「新規PR作成画面を開く」というタイミングで .github/PULL_REQUEST_TEMPLATE.md の中身を自動的にテキストエリアへ読み込みます。これはWeb UI側の機能であって、gh pr create というコマンド自体にはテンプレートを自動で挿入する仕組みはありません。

Claude Code は --body に本文を直接渡して gh pr create を実行するので、Web UIが担っていた「テンプレートを読み込む」という一手間がまるごと抜け落ちます。

AGENTS.mdの指示自体は常にAIに読み込まれますが、PR作成時にはブランチ差分・コミットログ・関連Issueなど参照すべき情報が他にもたくさんあります。その中で「テンプレートに従う」という一行の運用ルールは、優先順位が上がりにくく、実行のたびに再現される保証がありませんでした。

同じような課題は自分のリポジトリだけの話でもなく、Claude Code本体のリポジトリにも関連するIssueが上がっていました（anthropics/claude-code#6802）。「AGENTS.mdに書けば読むはず」という前提そのものが、gh コマンド経由の実行では崩れるということです。

対応: 運用ルールをSkillとして切り出した

Claude Codeには Skill という仕組みがあります。特定のそのタスク専用の手順書として確実に読み込まれる仕組みで、「PRを作って」「PRの説明を直して」といった依頼に対してだけ発火させることができます。

そこで、AGENTS.mdに書いていた運用ルールを .claude/skills/create-pr/SKILL.md という手順書に切り出しました。

---
name: create-pr                                                                                                                     description: GitHub Pull Requestを新規作成する、また。ユーザーがPRの作成、PR本文の作成・修正、またはPR説明の更新を依頼したときに使用する。
---                                                                                                                                 
# Pull Requestの作成・更新

`.github/PULL_REQUEST_TEMPLATE.md` をPR本文の構成の正本として使用する。                                                             
## コンテキストの確認

- ベースブランチ、現在のブランチ、ベースブランチとの差分とコミットを確認する
- 作業ツリーに未コミットまたは未追跡の変更がある場合は、PRに含まれる変更と区別する
- 既存PRの更新時は、現在のタイトルと本文も確認する
- Issue番号、動作確認結果、リリース作業など、確認できない情報を推測しない

## 本文の作成

テンプレートを本文構成の基礎として使い、内容のある見出しだけを残して、現在の最終的なコード状態に基づいて記載する。

- 記載できる内容がないセクションは、テンプレートに見出しがあっても見出しごと削除する

ポイントは、AGENTS.mdとSkillで役割を分けたことです。AGENTS.mdには規約を重複させず、次の1行だけを残しました。                        - Claude CodeでPull Requestを作成または説明文を更新 llを使用する
- AGENTS.md: 常に読まれる前提の、リポジトリ全体の方針・ルーティング
- Skill: 「PR作成・更新」という具体的なタスクが来たときに、確実に呼び出される手続き
                                                                                                                                    「守ってほしいルール」を指示ファイルに書き足すのではく手続き」として外に出したことで、gh pr create経由でもテンプレートの構成が安定して守られるようになりました。

ついでにテンプレート自体もシンプルにした

Skill化と合わせて、PRテンプレートに「リリース作業」セクションを追加しました。ただし固定のチェックリストにはしていません。

## リリース作業

<!-- 本番リリース作業者が気をつけるべきことを簡潔に記載（例: DBマイグレーション、環境変数/Secret変更、デプロイ順序、ダウンタイム、切り戻し手順など。列挙は例であり網羅ではない）。気をつけることがなければ本項目ごと削除してよい -->

「該当事項がなければセクションごと削除する」というルールをSkil側にも明記したことで、本番リリース時に気をつけることがない大半のPRでは、この見出し自体が本文から消えます。テンプレートに項のままPR本文に残って冗長になる、ということがなくなりました。

まとめ

「AIに常に守ってほしいルールは、指示ファイルに書けば十分」とは限りません。gh コマンド経由のように、Web UIが担っていた前提が崩れる実行経路では、指示ファイルの一行よりも、タスクに紐づいたSkillとして手続き化したほうが安定して再現されました。
