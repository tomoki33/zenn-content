## 起きたこと

Claude Code に「PRを作って」と頼むと、リポジトリの `.github/PULL_REQUEST_TEMPLATE.md` を無視した本文が出てくることがありました。

AGENTS.md にはこう書いていました（Claude Code は AGENTS.md を直接は読まないので、`CLAUDE.md` から `@AGENTS.md` でインポートしています）。

```md
- PRの本文は `.github/PULL_REQUEST_TEMPLATE.md` の構成に従う
- 内容のないセクションは削除する
```

実際、GitHubのWeb UI経由でPRを作るときは、テンプレートが自動で読み込まれます。
ただ Claude Code が `gh pr create` でPRを作ると、空の見出しが残ったままだったり、そもそもテンプレートと違う構成の本文になったりすることがありました。

## なぜ gh pr create では効かないのか

GitHubのWeb UIは「新規PR作成画面を開く」タイミングで `.github/PULL_REQUEST_TEMPLATE.md` の中身を自動的にテキストエリアへ読み込みます。

`gh pr create` にもテンプレートを扱う仕組み自体はあります。対話モードで実行するとリポジトリ内のテンプレートを検出して選択を促してくれますし、`--template` オプションで明示的に指定することもできます。

問題は Claude Code の呼び方です。Claude Code は `--body` に本文を直接渡して `gh pr create` を実行します。`--body` を渡すと本文のプロンプトはスキップされ、テンプレートは一切参照されません。Web UIやgh対話モードが担っていた「テンプレートを読み込む」という一手間が、この経路ではまるごと抜け落ちます。

AGENTS.md に書いておけば補えるかというと、これも安定しませんでした。
AGENTS.md は毎セッション読み込まれますが、PR作成時にはブランチ差分・コミットログ・関連Issueなど参照すべき情報が他にもたくさんあります。その中で「テンプレートに従う」という一行の運用ルールは埋もれやすく、実行のたびに再現される保証がありませんでした（自分の観察ベース）
Claude Code 本体のリポジトリにも同じ Issue が上がっていました（[anthropics/claude-code#6802](https://github.com/anthropics/claude-code/issues/6802)）。
「`--body` を付けずに実行してテンプレートを効かせる」か「テンプレートを読んで本文に反映する」かのどちらかにしてほしい、という内容です。
コメントでカスタムスラッシュコマンド（現在の Skill）として手順を定義する回避策が提案されていました。

## 対応: 運用ルールをSkillとして切り出した

Issue のコメントにならって、AGENTS.md に書いていた運用ルールを SKILL.md に切り出しました。

```md
---
name: create-pr
description: GitHub Pull Requestを新規作成・更新する。ユーザーがPRの作成、PR本文の作成・修正、またはPR説明の更新を依頼したときに使用する。
---

`.github/PULL_REQUEST_TEMPLATE.md` をPR本文の構成の正本として使用する。
内容のある見出しだけを残し、記載できる内容がないセクションは見出しごと削除する。
```

AGENTS.md 側には「PRの作成・更新は `create-pr` Skill を使う」という1行だけを残しています。

Skill は依頼が来たタイミングで手順書ごとコンテキストに入るので、常時読み込まれる AGENTS.md の中で埋もれることがありません。確実に効かせたいときは `/create-pr` と明示して呼び出せます。

これで、テンプレートを無視した本文や空の見出しだらけの冗長なPR説明が出てくることはなくなりました。
「AIに守ってほしいルールは AGENTS.md に書けば十分」とは限らず、タスクに紐づく手順は Skill に出したほうが安定します。
